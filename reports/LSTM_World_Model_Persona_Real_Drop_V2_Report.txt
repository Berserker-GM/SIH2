      <persona_id>__<hash>.csv per persona (first drop). That lacked
      run_000/001/002 structure and under-sized recon/C2/exfil
      (~200–700 windows vs ~1,600 intended).

  (B) Nested / disconnected from default ingest

        persona-gen/persona-gen/data/raw/personas/

        data/raw/personas/   (7-stage fixtures: benign_office_v1, …)
      Without --personas-dir (or a replace), prepare_dataset never sees
      the generator. Running adaptive from inside the nested folder
      without PYTHONPATH=<repo root> silently falls back to
      generator/score_stub.py.

--------------------------------------
Compared generator schema against world-model contracts:

  FEATURE_COLUMNS  ==  STATE_FEATURE_ORDER     (exact match)

CLI / runtime:

  --personas-dir     accepts any path relative to repo root
                     (default remains data/raw/personas)
  --write-persona-fixtures
                     writes 7-stage stubs ONLY if that personas dir
                     currently has no CSVs. Omit when real generator
                     data is present — otherwise stubs never fire.
  score_history(x, model_version="v2")
                     returns attack_probability, something_bad, stage,
                     technique_id, why_attack_top_features, why_stage,
                     why_change, ood_* fields.
  train --tag v2     writes world_lstm_v2.pt / scaler_v2.npz /
                     stage_decoder_v2.joblib / metrics_v2.json
                     and refuses to overwrite v1 without --overwrite.
  conftest.py        adds src/ subdirs to path, NOT repo root —
                     adaptive needs PYTHONPATH=<repo root> for
                     `from src.world_model.service import score_history`.
  .env.example       Redis/API ports only — not required for train.


4. CODE CHANGE THIS PASS
------------------------
File: src/world_model/dataset.py

  DAY_ID_DTYPE  "U64"  →  "U128"

Reason: synthetic day ids are `syn:{persona_id}:{run_id}` and
produce_dataset sets run_id = "{pid}__run_{idx:03d}". For
recon_service_discovery_v1 that string is 66 characters; U64
truncated to `…__run_0`, collapsing all eight runs into one day id
and breaking train/val/test-by-run splits. After the bump, all
eight run ids remain distinct.

No change to model.py, STATE_FEATURE_ORDER, or STAGE_NAMES.
