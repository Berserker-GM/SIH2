0. WHICH SIH TASK THIS IS
-------------------------
Problem statement (Section 2):

  “Represent network state using feature vectors and graphs.”

This is the STATE REPRESENTATION task. It is NOT “use a GNN as the
dynamics model.” LSTM remains the frozen world model (2×64, 32-d).


1. WHAT WAS ALREADY TRUE
------------------------
Feature vector S_t
  32-d, every 5 seconds, from CICFlowMeter columns.
  Indices 0–21 flow-level, 22–28 packet-level, 29–31 PCAP stubs = 0.
  This is what the LSTM sees. Unchanged.

Temporal “state graph” on the dashboard
  A chain t-7 → … → t → Ŝ_{t+5s} → … → Ŝ_{t+30s}.
  That visualises P(S_{t+1} | history). It is not a communication graph.


2. WHAT WAS MISSING
-------------------
A graph of WHO talks to WHOM in the same 5-second bin as S_t.

CIC ML CSVs omit Src IP / Dst IP, so a host graph was previously
declared impossible without PCAP. That is only half true: dest ports
are always present, so a service graph is well-defined on the same
files the LSTM was trained on.


3. REPRESENTATION (DUAL, SAME WINDOW)
-------------------------------------
For each 5-second bin:

  S_t  ∈ R^32     feature vector (LSTM input, frozen)
  G_t  = (V, E)   directed communication graph (sidecar, not LSTM input)

Host mode (Src IP and Dst IP present — GeneratedLabelledFlows / PCAP)
  V = hosts
  E = aggregated Src IP → Dst IP
      edge weight = flow count, bytes, packets

Service mode (CIC-IDS2018 TrafficForML default)
  V = one “unobserved sources” node + dest-port nodes
  E = unobserved → dest port
  Honest about missing IPs. A port-scan still looks like a STAR
  (high out-degree from the client supernode). A flood looks like
  high in-degree on one dest port.

Host–service mode (only Src IP)
  V = source hosts + dest ports
  E = host → dest port

Graph stats (for the defender, not for input_dim):
  n_nodes, n_edges, n_flows
  max_out_degree  (fan-out / scan)
  max_in_degree   (fan-in / flood)
  density, hub
